# Region identity and coupled surface labels — rejected real-image candidate

Scope: new Core/Interpolation offline tools and bounded source-pair rendering. No UI, source video, decoder, production shaders or dependencies changed. NumPy/Pillow already installed are offline analysis only. Apple M4. This is not a real-time implementation or a Motion²-equivalence result.

`RegionSurfaceProbe.py` extracts four-connected flat regions separated by Y/UV edges, evaluates component moments, positive-determinant affine shape coverage, area/color compatibility, and reciprocal region matches. No facial ROI, manually provided motion, semantic class or movie title enters matching. Three explicit edge thresholds are reported rather than choosing one from a desired final image. The following experiment uses2/255. At300s that gives29/23regions and14reciprocalmatches. The face-colored components are among these matches: their centers move roughly(-224,-65) work pixels. That numerical proximity to a manually observed head trajectory is diagnostic evidence only, not exact per-pixel truth. Region identity changes with shadow/pose, and several other reciprocal matches are wrong.

`RegionSurfaceRegularized.py` retains original dense motion, identity, and each reciprocal region-affine model as separate labels. Robust YUV data, bounded spatial support, edge-aware neighborhood cost and forward/reverse label closure select hypotheses without averaging different layers. A matched-region support prior supplies evidence for textureless interiors. Its small synthetic fixture demonstrates why that prior matters: without it a known flat-surface translation stays partly atzero despite correct boundary evidence; with the prior interior flow is exactly+8/-8px. Static input remains exact. This fixture validates only a translated flat region, not nonrigid facial pose recovery.

Both scripts have `--selfcheck`. Connected-run labeling checks disconnected/connected/empty masks. The regularized solver checks the exact translated region, reverse motion, finite output and static identity. Covariance uses explicit reduction rather than platform BLAS, avoiding spurious floating-status warnings observed on the installed NumPy backend.

The direct renderer `SurfaceSynthesisRender.sh` reads bounded8-bit grayscalePNG and Float4 flow fields, invokes actual production denseProject/denseSynthesize, and reports mapping residuals/folds. Optional SURFACE_REASSESS=1 recomputes field confidence/visibility with production blur+assessment after modifying xy; otherwise source field z/w would be stale. It changes no production shader. The inverse-iteration variant remains an explicit isolated diagnostic. Static64×48 input with zero flow was pixel-exact at allthree rendered times. PNG quantization means real-image runs are approximate reproductions of native10-bit luma, not full-color playback validation.

## Real result and rejection

Direct replacement, independently regularized labels, coupled labels, and coupled labels with support prior all fail the visual requirement at300s: face sections become clearer locally, but duplicate facial outlines and fragmented clothing remain. Recomputed visibility does not remove them. These counts differ from earlier probe counters because the diagnostic boundary and accounting differ; do not compare them as a universal defect percentage.

Do not integrate this selector into Frame+. Region shape and color add useful proposals but do not establish that all visible parts of a changing3Dpose belong to one supported2Dmap. A lower photometric cost or a cleaner flat region must not be reported as a deformation fix.
